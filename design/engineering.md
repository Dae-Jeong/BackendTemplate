규칙이 해당되지 않는 기능에 빈 계층을 생성하지 않습니다. 지속적인 예외는 소유 문서에서 이유·범위를 정합니다.

## 코드와 업무 표현

- 이름은 수행하는 업무를 표현하고 입력·반환 타입을 명시합니다. 언어·프레임워크의 관용적 API를 우선합니다.
- 형태가 고정된 업무 데이터는 이름 있는 필드의 typed model로 표현합니다. 외부·저장 payload는 경계에서 한 번 runtime validation한 뒤 업무에서는 typed field로 접근하고 native serializer를 사용합니다. static type은 runtime 보장이 아니며, 실제 동적 map·protocol label은 map으로 유지하고 단순 값을 빈 DTO로 감싸지 않습니다.
- 예외는 복구·오류 번역·작업 격리 책임이 있는 경계에서 처리합니다. 불명확한 실패를 정상 값으로 숨기지 않습니다.
- 이벤트 루프에서 blocking I/O를 실행하지 않습니다. 순수 계산에 불필요한 비동기 선언을 붙이지 않습니다.
- 도메인은 상태·불변조건·허용/금지 전이를 보호합니다. 자주 바뀌는 정책과 안정된 엔티티를 분리하고 중요한 정책 결정의 버전·결과·사유를 필요에 따라 추적합니다.
- 정밀한 금액은 십진 타입 또는 최소 단위 정수를 사용합니다. 사건 시각은 timezone-aware UTC로 처리하되 생일·현지 영업일·반복 일정은 원래 시간 의미를 보존합니다.
- 복잡한 매핑은 순수 변환과 업무 판단을 구분합니다. 표현 변환 중 lazy loading·외부 조회·상태 변경을 수행하지 않습니다.

## Application과 입력 경계

- 업무 흐름은 SQL을 직접 작성하지 않으며 HTTP 전용 객체·ORM 객체를 외부 계약으로 반환하지 않습니다.
- 구조화 결과가 필요할 때 내부 타입을 사용하고 단순 값에 빈 DTO나 wrapper를 추가하지 않습니다.
- 다른 도메인의 정보는 소유 도메인의 조회 계약을 통해 얻고 순환 업무 호출을 만들지 않습니다.
- 여러 업무를 실제로 조합할 때만 Facade를 사용합니다. 단일 호출을 포장하거나 Facade를 중첩하지 않습니다.
- 외부 조회를 필요로 하는 재사용 검증은 분리할 수 있지만 Validator가 상태 변경·트랜잭션을 소유하지 않습니다.
- 입력 경계는 형식·프로토콜 인증 문맥·응답을, 업무는 자원 권한·정책을 소유합니다. 합성 사용자를 운영 인증으로 설명하지 않습니다.
- Job은 업무 흐름을 호출하며 직접 SQL·외부 호출·다른 Job 호출로 업무를 구성하지 않습니다. 중복·재시작·부분 실패 정책을 정의합니다.

## DB와 외부 연계가 추가될 때

- Repository는 업무 의미의 조회·저장과 scope 조건을 소유하고 ORM을 경계 안에 유지합니다. 저장 입력도 명시적인 타입으로 전달합니다.
- `python/fastapi-fastcrud/`는 model별 FastCRUD API 자체를 저장 경계로 사용하는 명시적 예외입니다. 이 변형만 Service가 typed storage schema로 FastCRUD를 직접 호출하고, `crud/`에는 model별 객체와 특수 SQL만 두며 forwarding Repository·`BaseCRUD`를 만들지 않습니다. 업무 정책과 transaction 경계는 계속 Service가 소유합니다.
- schema 변경은 migration과 함께 다룹니다. enum·제약·인덱스·pagination 정렬을 실제 DB에서 검증합니다.
- 한 세션을 동시 task에 공유하지 않습니다. 병렬 세션 사용으로 원자성이 달라지면 이를 명시합니다.
- flush는 commit이 아닙니다. 경합은 선조회만으로 막지 않고 제약·잠금·조건부 변경으로 불변조건을 보호합니다.
- 독립 서비스·DB 간 전체 원자성을 로컬 transaction으로 주장하지 않습니다. 재시도·보상·재개 계약을 정합니다.
- DB 변경과 이벤트 전달을 함께 보장해야 할 때 outbox 등 복구 방식을 검토하며 단순 after-commit 호출로 전달 보장을 주장하지 않습니다.
- 외부 Port는 필요한 행위만, Adapter는 값·오류 변환을, Client/SDK 경계는 인증·통신·timeout을 소유합니다. 책임 구분이 항상 별도 클래스 세 개를 요구하지는 않습니다.
- 누락된 외부 필드·알 수 없는 상태·잘못된 타입을 정상 빈 값으로 바꾸지 않습니다. 거절·인증 실패·일시 장애·결과 불명을 구분합니다.
- 연결/응답 timeout·전체 시간 예산과 재시도 주체·횟수·backoff·jitter·상한을 정합니다. SDK와 앱에서 재시도를 중첩하지 않습니다.
- 비멱등 쓰기는 중복 효과를 고려하지 않은 자동 재시도를 금지합니다. timeout 뒤 이미 처리됐을 가능성은 조회·대사·복구로 다룹니다.
- circuit breaker·fallback은 실제 필요가 있을 때만 사용하며 오래된 결과를 정상 최신 결과로 숨기지 않습니다.

## 검증과 범위 관리

정상 결과뿐 아니라 실패 시 변경되지 않아야 할 상태·외부 호출 횟수도 검사합니다.
시간·의존성을 제어하며 기본 테스트는 외부 API 대역으로 실행합니다. 실제 DB의 제약·잠금은 격리된 실제 DB로 검증해야 합니다.
대역 테스트 성공과 실제 provider 계약 검증을 구분하고 운영·공유 자원 변경을 테스트 준비라는 이유로 수행하지 않습니다.
기준을 맞추기 위해 실패한 테스트를 제거하거나 통과 임계치를 조용히 완화하지 않습니다.

TDD는 현재 의무 개발 방식이 아닙니다. 시험 작성 순서를 강제하지 않되 검증 증거는 요구합니다.
새 도구·캐시·브로커는 제품 요구·운영 문제 또는 명시적인 학습 목적이 있을 때 도입합니다.
실행 계획은 시작할 작업의 파일·의존성·통과 조건으로 작성하고, 아직 없는 명령·doctor·성능 결과를 만들지 않습니다.
