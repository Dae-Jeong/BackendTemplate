# Runtime Review — 성능·용량 판단 기준

Status: 설계·리뷰 기준 정본 · 자동 하네스 미구현 · 2026-09-07

언어·실행 모델·worker·연결 풀·큐·용량을 선택하거나 변경할 때만 읽습니다. 일반 문구 수정에는 요구하지 않습니다.

[설계 안내](README.md) · [개발 원칙](engineering.md) · [구현별 설계 안내](implementations/README.md)

    GOAL["업무 목표와 부하 가정"] --> HYP["런타임·I/O 병목 가설"]

| 계층 | 확인할 사항 |
| --- | --- |
| 업무·부하 | 요청률·동시 연결·읽기/쓰기·데이터 크기·키 편중·정합성입니다. |
| 언어·런타임 | 실제 버전/빌드의 GIL·GC·event loop·객체 할당과 해당 업무 경로의 연관성입니다. |
| 프로세스·OS | worker별 RSS·스레드·pool·CPU 제한·throttling·파일 디스크립터입니다. |
| DB·외부 I/O | 쿼리·잠금·pool 대기·외부 지연·재시도 전파입니다. |
| 과부하·복구 | 유입 제한·queue 포화·거절·재접속·복구 시간입니다. |

실제 경로에 관련된 계층만 선택하고 제외한 이유를 남깁니다. 용어를 언급하는 것으로 검토를 완료하지 않습니다.
구현체·버전·공식 자료와 해당 경로에 대한 가설을 구분하며 보편적인 언어 우열로 결론 내리지 않습니다.

시험 전 기록: 사용자 목표·불변조건, 예상 부하, 병목 가설과 대안, 코드 revision·환경·worker/pool,
공식 출처·확인일, 재현 명령·격리 대상·워밍업·지속 시간·반복·임계치입니다.
시험 후 기록: 원시 결과 위치, 측정값, 판정, 누락 데이터·한계, 재검토 조건입니다.

- 미검증·통과·실패·판정 불가·해당 없음(이유)을 구분합니다. 설계 승인은 성능 통과가 아닙니다.
- 유입·성공·오류·거절을 함께 보고 p95/p99는 구간·표본 수와 비교합니다. 인스턴스별 percentile을 단순 평균하지 않습니다.
- 부하 생성기의 CPU·네트워크 제한을 확인하며 로컬 결과를 더 큰 규모나 다른 배포의 보장으로 일반화하지 않습니다.
- 빨라져도 누락·중복·권한·순서 불변조건을 깨면 실패입니다. 결과를 본 뒤 임계치를 낮추지 않습니다.
- 필수 측정값이 없으면 통과하지 않습니다. 자동 검사 도입 시 위반을 주입해 실패 감지를 확인합니다.
- 월 비용은 실측 처리량과 수요·단가·보관·복제 가정을 분리해 계산합니다. 임의 수치를 공통 표준으로 고정하지 않습니다.

이 문서는 판단 기준이며 부하 도구 설치·공유 자원 실험·비용 발생을 승인하지 않습니다.
